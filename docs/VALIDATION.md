# Проверка локального продукта

Дата: 2026-10-07. Среда выполнения: Linux, Python 3.11, Node.js 22,
Chromium, CPU ONNX Runtime 1.23.2. Результаты ниже относятся к этой среде;
физические камеры Mac/Windows и промышленная площадка ещё не проверялись.

## Автоматические проверки

- Backend: **39 тестов прошли**, `ruff check` без ошибок.
- Frontend: **4 теста машин состояний прошли**, TypeScript/Vite production build успешен.
- `git diff --check` без ошибок.

Backend проверяет подтверждение и завершение нарушения, повторное появление,
пропуск кадров, отсутствие ложного нарушения при неизвестном СИЗ,
конфликтующие PPE-предсказания, tracking, границы и валидацию зон,
сохранение снимков/инцидентов, перезапуск, терминальные статусы,
отказ детектора и записи снимка. Интеграционные API-проверки проверяют
идентификатор сессии, запоздавшие кадры/остановки, точный кадр по sequence,
отменённую и пустую загрузку. Telegram проверен с управляемым HTTP-транспортом:
multipart-снимок, успешная доставка и ошибка без раскрытия токена.

Проверка Windows выявила одинаковые значения монотонных часов на быстрых
кадрах. Расчёт FPS теперь проверяет положительный интервал; отдельный тест
проверяет, что одинаковые ticks не прерывают обработку и сохранение события.

Frontend проверяет допустимые переходы захвата, остановку,
обработку ошибок и запрет одновременных команд.

## Реальная модель и браузер

Две скачанные ONNX-модели с проверенными SHA-256 обработали публичное
изображение `bus.jpg` из примеров Ultralytics. Детектор людей вернул четыре
человека с уверенностью около 89%, 88%, 88% и 44%; PPE-модель также вернула
`no_vest` с уверенностью около 52%. Это smoke-проверка инференса,
не измерение точности на производстве.

В Chromium тот же публичный кадр подавался как тестовый видеопоток камеры;
предсказания не подменялись. Проверены:

1. Запрос браузерной камеры, запуск, остановка и повторный запуск.
2. Рамки, названия объектов, реальные проценты уверенности и карточки работников.
3. Рисование/сохранение polygon-зоны и четыре подтверждённых события входа в неё.
4. Совпадение рамок с точным обработанным кадром, включая портретное изображение.
5. Сохранение имени камеры, мобильный экран без горизонтального переполнения.
6. Отсутствие JavaScript-ошибок в проверенном сценарии.

## Реальное видео

Загружен тестовый MP4 длиной 12 секунд: 7 секунд публичного кадра с людьми,
затем 5 секунд чёрных кадров. Через новый протокол загрузки и реальный ONNX
получены **три события опасной зоны**, все перешли в `resolved` после
исчезновения людей. Источник перешёл в `ended`, URL точного исходного кадра
остался доступен в пределах кэша. Проверка повторена после введения
машин состояний и моделей ответов API.

## Ограничения проверки

- Две модели вместе занимали около 625–705 мс на кадр в этой среде
  (примерно 1,4 кадра/с). Это не обещание производительности на другом CPU.
- Headless-камера проверяет browser capture/API, но не драйвер физического устройства.
- Для RTSP необходима проверка с конкретной камерой, URL и сетью пользователя.
- Реальное Telegram-сообщение не отправлялось: нужен токен/чат пользователя.
- CI настроен на Linux, Windows и macOS; фактический результат конкретного
  запуска смотрите в GitHub Actions, а не считайте эту конфигурацию доказательством.
- Precision/recall PPE и устойчивость ID в толпе требуют отдельного датасета
  площадки. Проценты — уверенность модели, не вероятность безопасности.
- Веса и публичные тестовые кадры не включены в репозиторий;
  происхождение/лицензии указаны в [THIRD_PARTY.md](../THIRD_PARTY.md).

Для повторной проверки модели на своём кадре:

```bash
python backend/scripts/smoke_model.py /path/to/frame.jpg
```

Запускайте команду из корня репозитория, используя Python установленной `.venv`.
