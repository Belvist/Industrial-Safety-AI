# Separate-device testing / Испытания на независимых компьютерах

## Почему появляется 401 на https://192.168.*:8000

Это **защищённый LAN-сервер**. Запросы /api/v1/cameras и /api/v1/incidents требуют токен.
Обычный переход по IP без ключа возвращает 401 **по замыслу**, не свидетельствует
об ошибке ONNX. На экране оператора теперь есть форма ввода ключа.

Оператор на том же компьютере:
1. Остановить старый backend (Ctrl+C). Выбрать актуальную ветку и собрать фронтенд.
2. Запустить `python3.11 run.py --lan` (Windows: `py -3.11 run.py --lan`).
3. Launcher автоматически откроет браузер с операторским ключом, который затем
   хранится только во вкладке (`sessionStorage`), а `?token=` удаляется из адреса.
4. Если открыли `https://<LAN-IP>:8000/` вручную и видите 401, нажмите «Войти»,
   вставив содержимое **локального** файла `data/api_token`. Никому не отправлять
   файл/токен/скрин с ключом.
5. Если `API_TOKEN` установлен через .env или переменную окружения, используется
   **этот** токен, а не обязательно `data/api_token`.

На сервере фреймы могут приходить с телефона после QR в «Камеры и правила».
Для каждого телефонного подключения используется отдельный ограниченный токен.
Это **не** полноценная multi-tenant система с учётными записями.

## Независимая проверка другим человеком: предпочтительный способ

**Пусть тестировщик запускает отдельную копию на СВОЁМ компьютере.**

1. Выдать доступ только к нужному исходному коду/архиву этой ветки
   (репозиторий приватный: не пересылать пароль/личный GitHub token).
2. На компьютере тестировщика получить чистую копию **без** `data/`, `.env`,
   `.venv/`, `frontend/node_modules/`, снимков и локальных ключей.
3. Установить Python 3.11 и Node.js 22. В новой папке выполнить:
   - macOS/Linux: `python3.11 run.py`
   - Windows: `py -3.11 run.py`
4. Открыть `http://127.0.0.1:8000` на **его** компьютере. Камеры, SQLite,
   снимки и настройки будут созданы в **его** локальном `data/`.
5. При необходимости уведомлений тестировщик сам задаёт Telegram токен/чат
   в своём `.env`. По умолчанию Telegram отключён.
6. Тестировщик не должен обращаться к `https://192.168.1.194:8000`:
   этот адрес ведёт на ЧУЖОЙ backend и общую серверную машину.

Без облака и общих URL данные этих установок **не синхронизируются**.
Можно проверить сетевые IP/RTSP камеры только в пределах доступной тестировщику сети.

## Что остаётся не реализовано

- Полноценная регистрация множества операторов и централизованное разделение
  tenants/users/devices на одном сервере.
- Хранение телефонных ключей между рестартами и восстановление собственных
  workspace для телефона: после рестарта требуется новый QR.
- Настоящее устройство LinQ, подтверждённая точность PPE на промышленном видео,
  живой Telegram/RTSP/физический iOS/Android тест.

Для пилота с несколькими независимыми организациями нужна серверная модель
tenant_id/user_id/device_id, scoped keys с отзывом, политика доступа к evidence,
шифрование/retention и интеграционное тестирование доступа между tenants.
