# Industrial Safety AI

Локальное приложение для контроля каски, жилета и опасных зон по видеопотоку.
Камера → ONNX → tracking → правила → подтверждение во времени → инцидент → снимок / SQLite / Telegram.

## Быстрый запуск на Mac и Windows

Требуются **Python 3.11 или 3.12** и **Node.js 22 LTS**. При первом запуске нужен интернет для зависимостей и двух ONNX-моделей (~117 МБ). После установки обработка работает локально; интернет нужен только для Telegram/сетевых камер.

Скачайте репозиторий, откройте терминал в его папке:

```bash
# macOS / Linux
python3.11 run.py
```

```powershell
# Windows
py -3.11 run.py
```

Либо запустите `start.bat` на Windows / `bash start.command` на Mac. Скрипт создаст `.venv`, установит зависимости, соберёт интерфейс, проверит контрольные суммы моделей и откроет **http://127.0.0.1:8000**. Повторный запуск использует уже установленные файлы. Остановка — Ctrl+C в терминале.

Если используете Python 3.12, замените `3.11` на `3.12`. Если команды не найдены, установите Python с python.org и Node.js с nodejs.org и заново откройте терминал.

```bash
python3.11 run.py --setup-only   # только установка
python3.11 run.py --no-browser   # запуск без открытия браузера
```

## Как пользоваться

1. Откройте «Мониторинг». Статус детектора должен быть «готов».
2. Выберите веб-камеру (кнопка «Найти камеры» запрашивает разрешение браузера), видеофайл до 200 МБ или RTSP/HTTP URL и нажмите «Запустить».
3. Включите контроль каски/жилета. Для зоны нажмите «Опасная зона», поставьте минимум три точки поверх изображения и сохраните.
4. На кадре отображаются блоки распознанных объектов и уверенность в процентах; под кадром — список детекций, справа — результаты СИЗ каждого Worker ID.
5. Длительность подтверждения и завершения настраивается в «Камеры и правила». По умолчанию — 2 секунды.
6. Откройте инцидент: доступен снимок, Worker ID, время, уверенность и кнопки «Подтвердить» / «Ложное срабатывание».

Веб-камера обрабатывается, пока вкладка открыта; разрешение выдаётся браузеру. RTSP и видеофайлы обрабатывает backend. Для локального приложения открывайте **localhost / 127.0.0.1**, а не адрес другого компьютера. На Mac разрешите браузеру камеру в «Системные настройки → Конфиденциальность и безопасность → Камера»; на Windows — в настройках конфиденциальности камеры. Если устройство занято Zoom/Teams, закройте использующую его программу.

## Telegram и конфигурация

Скопируйте `.env.example` в `.env` в корне. Для уведомлений заполните:

```dotenv
TELEGRAM_ENABLED=true
TELEGRAM_BOT_TOKEN=your-bot-token
TELEGRAM_CHAT_ID=your-chat-id
```

Начните диалог с ботом / добавьте его в нужную группу и перезапустите приложение. При создании инцидента бот отправляет снимок и описание. Статус доставки виден в карточке. При ошибке доставка помечается `failed`; автоматических повторов и Telegram-кнопок в этой версии нет. Оценка оператора сохраняется через веб-интерфейс.

Все относительные пути вычисляются от корня репозитория, независимо от текущей папки. База: `data/safety.db`, снимки: `data/snapshots/`, временные видео: `data/uploads/`. Видео удаляется после окончания обработки. История и снимки сохраняются до ручной очистки при остановленном приложении. `.env`, модели и runtime-данные не коммитятся.

## Выбор модели PPE

Стандарт: `models/ppe.onnx` (Hexmon). Явный выбор — через `.env`:
`MODEL_PATH=models/ppe-v4cloud.onnx`. Установщик (`backend/scripts/download_model.py`)
проверяет SHA именно выбранного файла по реестру версий и отказывается ставить
неизвестное; `PPE_ROI_MODE=off` отключает ROI-кропы. Откат:
`backend/scripts/download_model.py --rollback` (нужен `<model>.bak`).
Пороги при смене модели не меняются. Актуальные замеры моделей — в `training/`.
Одномодельный режим (`USE_SEPARATE_PERSON_MODEL=false`, person из самой PPE-модели)
поддержан и замерен, но по умолчанию включён dual. Откат:
`backend/scripts/download_model.py --rollback` (нужен журнал выбора).

## Что работает и как интерпретировать результаты

- Настоящий ONNX-инференс на CPU: отдельная YOLOv8n-модель людей + PPE-модель касок и жилетов.
- Нормализованные координаты, IoU tracking, привязка СИЗ к человеку, контроль точки под ногами в polygon-зоне.
- Явная детекция `no_helmet` / `no_vest` подтверждается во времени. Просто невидимая каска/жилет даёт «не определено» и не создаёт нарушение.
- Один непрерывный проступок — один `ACTIVE` инцидент. Отсутствие наблюдаемого нарушения в течение `clear_seconds` переводит его в `RESOLVED`.
- Остановка/потеря источника, изменение правил или перезапуск сервера помечают незавершённое наблюдение как `INTERRUPTED`, а не как устранённое нарушение.
- Камеры/правила, история и feedback сохраняются в SQLite. Имена камер сохраняются; приватные RTSP URL — только в памяти.

Это рабочий локальный MVP. IoU tracking может менять ID при пересечениях и длительных перекрытиях; `RESOLVED` означает отсутствие наблюдаемого нарушения, а не доказанную безопасность работника вне кадра. Точность PPE зависит от ракурса/освещения и требует проверки на вашей площадке. При низком FPS подтверждение произойдёт на следующем обработанном кадре; долгий разрыв кадров сбрасывает ещё не подтверждённое нарушение. Интерфейс показывает измеренные FPS и latency, целевые 5 FPS не гарантируются. Начинайте с одной активной камеры на CPU. Приложение рассчитано на одного локального оператора и один процесс backend, без сетевого размещения и многопроцессного запуска.

LinQ остаётся отдельным адаптером: при `INFERENCE_PROVIDER=linq` интерфейс явно сообщает, что SDK ещё не подключён. Формат `Detection` и продуктовые модули менять не потребуется.

## Разработка и проверки

```bash
cd backend
python -m venv .venv
# macOS/Linux: source .venv/bin/activate
# Windows: .\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev,vision]" -c constraints.txt
python scripts/download_model.py
python -m pytest -q
python -m ruff check .
uvicorn app.main:app --reload --host 127.0.0.1
```

В другом терминале:

```bash
cd frontend
npm ci
npm run dev
npm run test
```

Vite доступен на http://127.0.0.1:5173 и проксирует API на порт 8000. Для единого сервера: `npm run build`, затем перезапуск backend. OpenAPI: http://127.0.0.1:8000/docs.

CI запускает backend-тесты на Python 3.11 в Linux, Windows, macOS и сборку frontend. Юнит/интеграционные тесты используют управляемый детектор, не скачивают веса и не отправляют реальные Telegram-сообщения. Реальный инференс проверяется отдельно: [проверка MVP](docs/VALIDATION.md).
